# Known limitations

These limitations are part of the release decision. They must not be hidden by aggregate PASS
language.

| Limitation                             | Impact                                                                                                                                                                                                 | Current mitigation                                                                                                                                                    | Production relevance                                                                                        | Future work                                                                                                                                    |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| External LLM dependency                | Live planning availability, latency, and output quality depend on the configured provider.                                                                                                             | Deterministic Tool/Policy/confirmation/executor boundaries; bounded timeouts; faux-provider CI; safe failure responses.                                               | High: provider outage or rate limiting can reduce service availability, but must not bypass safety.         | Add provider-specific SLOs, controlled failover evaluation, and periodic complete Native requalification.                                      |
| Provider rate and quota limits         | Live benchmark or runtime calls can be throttled or rejected; provider-internal retries are not exposed.                                                                                               | Explicit infrastructure attribution, no guessed retry counts, bounded admission/backpressure, and no cross-run result splicing.                                       | High for capacity planning; deterministic throughput figures exclude provider latency.                      | Qualify contracted quotas and provider-only latency in the intended deployment region.                                                         |
| Simulator rather than vehicle hardware | Execution evidence validates the DriveGuard service boundary and simulator semantics, not CAN, ECU, actuator, or functional-safety hardware.                                                           | RX actuator capabilities are never registered; the simulator is isolated behind the same Policy/confirmation/executor path.                                           | Critical boundary: this release is not evidence of a production-car deployment or certification.            | Perform separately governed HIL/SIL, vehicle integration, hazard analysis, and applicable safety certification.                                |
| Residual no-fixed-version image CVEs   | Each final image contains 43 raw High rows across eight CVEs; scanner count is not zero.                                                                                                               | Every row is retained and classified `NOT_REACHABLE`; runtime is non-root, read-only, no-new-privileges, capability-free, and does not invoke affected command paths. | Requires ongoing review even though final reachable/fixable/unclassified High and Critical counts are zero. | Rescan when a fixed version/base digest appears or any entrypoint, package, capability, or reachability assumption changes.                    |
| External PostgreSQL/Redis gated tests  | The final full suite executes 2,314 tests and skips 45 opt-in integration cases when external services are not supplied.                                                                               | Production Compose smoke, restart, persistence, audit, restore, and dependency drills cover the deployed topology separately.                                         | Moderate; skips are disclosed and are not counted as passes.                                                | Run the opt-in integration profile in an environment that provides its prescribed external services.                                           |
| CAR-bench upstream attrition           | Official CAR-bench raw Pass@1 is 41.60%; 47/125 trials were infrastructure failures, mainly upstream simulator/bridge behavior.                                                                        | Preserve raw and valid-only (66.67%) denominators, never average with Native scores, and retain every failed trial.                                                   | Low for runtime release; relevant to external benchmark interpretation.                                     | Re-run only against a pinned, repaired upstream version under a new explicitly comparable benchmark record.                                    |
| Deployment assumptions                 | Final evidence uses Docker Compose, local image digests, named volumes, a reachable JWKS issuer, and operator-managed secrets. No registry push or multi-host orchestration was verified.              | Fail-closed production configuration, internal networks, immutable SHA identity, runbooks, backups, restore, rollback, alerts, and smoke evidence.                    | High: operators must reproduce controls in the target environment.                                          | Add registry provenance/signing, deployment-specific secret management, disaster-recovery objectives, and orchestrator validation if required. |
| Deterministic capacity scope           | Qualified 20-VU/96.53 req/s and soak figures use a deterministic faux provider and the tested single-host topology.                                                                                    | Provider latency is reported separately; no public traffic, QPS, or user-scale claim is made.                                                                         | High for sizing: figures are engineering qualification points, not universal capacity.                      | Repeat load/soak with target hardware, network, provider quota, observability retention, and deployment configuration.                         |
| Historical Phase 15 mismatch evidence  | Three Phase 15.1 accepted-task mismatches lack per-case payloads and cannot be reconstructed.                                                                                                          | Phase 15.3 preserves the limitation, validates a negative harness, runs A–E race cases, and records 30/30 prospective observations with zero mismatch.                | Low for the final runtime, but important for audit integrity.                                               | Keep durable per-mismatch payload capture and never overwrite evidence in future performance runs.                                             |
| Hosted CI identity                     | The latest observed hosted green run is Phase 16 source `3c6526f…`; the Phase 18/main and Phase 19 closures are locally validated with the same repository commands, not yet observed as a hosted run. | Exact run identity is recorded; local final validation executes required contracts, safety, full regression, build, audit, Compose, diff, and layout checks.          | Release operators should require a green hosted run for the eventual pushed/tagged commit.                  | Push only after authorization and require the workflow to pass on the final integration SHA before publication.                                |

No limitation relaxes the hard safety metrics or authorizes a real-vehicle/commercial-production
claim.
