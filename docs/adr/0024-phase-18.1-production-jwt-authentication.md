# ADR 0024: Phase 18.1 production JWT authentication

## Status

Accepted for Phase 18.1, pending production operational verification.

## Context

The Phase 18 production overlay deliberately rejected startup because the API
only knew the development `x-driveguard-*` headers. Those headers are still
useful for deterministic local and CI fixtures, but they are not authentication
and cannot cross the production boundary.

## Decision

Production requires `DRIVEGUARD_AUTH_MODE=jwt` plus an issuer, audience, JWKS
URL, explicit allowed algorithm list, and a vehicle-scope claim name before
dependencies connect or the API listens. The API verifies a compact Bearer JWT
signature against the issuer JWKS using Node WebCrypto, accepts only RS256 or
ES256 when explicitly configured, and validates `iss`, `aud`, `exp`, `nbf`,
and a safe `sub`.

The verified `sub` becomes the internal `userId`; the client cannot supply it.
The configured vehicle-scope claim is the production `VehicleAuthorizer` input.
Every production route carries a validated vehicle selection in its body or
query field, never in a development identity header. The selected vehicle must
be present in the verified scope before session, action, confirmation, or
execution access reaches the service layer.

JWKS keys are cached for at most five minutes, and an unknown `kid` triggers
one forced refresh to permit normal key rotation. Errors fail closed with
controlled 401/403 responses and never include a token, JWKS body, or key.

## Consequences

The existing session/action/execution identity bindings remain intact and now
consume an identity derived only from a verified principal in production.
Development and test still use the clearly labelled header boundary. Existing
append-only audit records retain the derived authenticated `userId`, vehicle,
session, action, trace, policy, confirmation, and execution lifecycle data;
they never record Bearer credentials or JWT bodies.

Production release smoke, restart smoke, final scans, and candidate digest
capture remain required before the Phase 18.1 gate can pass.
