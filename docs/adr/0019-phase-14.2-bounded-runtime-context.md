# ADR 0019: Phase 14.2 bounded runtime reuse and model context

- Status: Accepted for Phase 14.2 implementation
- Date: 2026-09-08

## Context

Phase 14.1 showed uncontrolled load errors and long-run drift even though dependency queues and
connections stayed bounded. Phase 14.2 isolation and heap evidence traced the dominant cost to
constructing a complete Agent Runtime for every message, with additional risk from restoring an
ever-growing transcript and retaining process-local identifiers and trace parents indefinitely.

## Decision

Reuse an identity-bound Agent Runtime per active session. Store runtimes in an LRU whose capacity
equals process-wide HTTP admission concurrency, and forward each request's event/SSE sinks through
a mutable request slot. Reject any identity mismatch before reuse.

Limit model context to the most recent 40 durable conversation messages, trimming only on a user
turn boundary. Preserve the complete durable transcript, confirmation/action state, execution
receipt, idempotency record, and audit events in their existing structured repositories. Bound
process-local issued IDs and retain trace-parent context only while a confirmation is pending.

## Consequences

- Repeated messages no longer rebuild the complete Runtime graph.
- Runtime memory is bounded by admission concurrency and model input is bounded independently of
  durable business history.
- Event sinks stay request-scoped even when the Runtime object is reused.
- LRU eviction may rebuild a Runtime after saturation, but it cannot create an unbounded cache.
- A 160 MiB V8 old-space ceiling remains a fail-safe guardrail; admission, not heap growth, handles
  overload.

This decision does not alter Policy, Confirmation, Reliable Executor, Ground Truth, Scorer, or the
vehicle-actuator safety boundary.
