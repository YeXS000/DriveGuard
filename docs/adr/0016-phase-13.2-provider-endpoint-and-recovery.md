# ADR 0016: Phase 13.2 Provider Endpoint and Recovery Boundaries

- Status: Accepted for Phase 13.2 implementation
- Date: 2026-09-03

## Context

Phase 13.2 requires explicit OpenAI-compatible DeepSeek endpoint selection and deterministic
recovery. The
installed `@earendil-works/pi-ai` version is `0.84.3`. Its DeepSeek provider reads
`DEEPSEEK_API_KEY`, selects `deepseek-v4-flash` from the installed catalog, and stores the request
endpoint on the selected model's `baseUrl` field. The provider does not expose a separate DeepSeek
base-URL environment variable.

The final credential-backed development reruns use DeepSeek's documented official API base URL,
`https://api.deepseek.com`, rather than the earlier custom proxy. The override remains necessary so
the endpoint is explicit and independently auditable at runtime.

The existing executor retried generic transient errors and treated an idempotent downstream as
sufficient for retry safety. That is insufficient for ambiguous write outcomes: timeout or
connection abort can occur after the side effect.

## Decision

1. `DEEPSEEK_BASE_URL` may override the selected catalog model's `baseUrl`. It must be a
   credential-free HTTPS URL. `DEEPSEEK_API_KEY` remains the only credential source.
2. `deepseek-v4-flash` remains the text/tool-calling runtime model because it is present in the
   installed Pi catalog. No unverified vision model is synthesized into the catalog.
3. Recovery is deterministic. Explicit write timeout and connection-abort failures require
   reconciliation before any retry, including downstream-idempotent operations.
4. A retry after reconciliation is allowed only when the external state is `NOT_EXECUTED`, the
   operation is idempotent, and the bounded attempt budget remains.
5. External state `EXECUTED` completes from the reconciliation receipt; `UNKNOWN` stops further
   writes and produces safe degradation.

## Consequences

- Custom endpoints work without source or report credentials.
- The official endpoint can be selected explicitly without changing the model catalog or
  persisting credentials.
- Legacy generic transient errors keep their accepted Phase 8 behavior; new explicit failure
  metadata activates the stricter Phase 13.2 path.
- Ambiguous reservation timeouts add one read-only reconciliation request and no blind write retry.
