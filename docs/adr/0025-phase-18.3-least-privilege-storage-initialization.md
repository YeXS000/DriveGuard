# ADR 0025: Phase 18.3 least-privilege persistent-volume initialization

## Status

Accepted for the Phase 18.3 branch only; the overall release gate remains FAIL.

## Decision

Production PostgreSQL, Redis, and NATS remain non-root, read-only-rootfs
workloads with `cap_drop: [ALL]`. Separate one-shot, network-isolated volume
initializers prepare only their respective named volumes before runtime starts.
The initializers retain only the measured capability set required for their
idempotent ownership and mode checks: PostgreSQL `CHOWN,FOWNER`, Redis
`CHOWN,FOWNER,DAC_OVERRIDE`, and NATS `CHOWN`.

## Consequences

The production overlay does not use privileged containers, host networking,
`chmod 777`, root database runtimes, writable root filesystems, or `cap_add:
ALL`. An existing volume with an unexpected owner or mode fails initialization
instead of being recursively repaired. The test-only Compose overlay may enable
the controlled simulator development route solely to exercise the R2 Policy and
confirmation chain; the deployable production overlay remains read-only.
