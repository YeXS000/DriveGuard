# ADR 0017: Critical Policy Precheck and Bounded Plan Repair

## Status

Accepted for Phase 13.2.1.

## Context

Phase 13.2 demonstrated that a stochastic model can omit or malform a required critical Tool
proposal. Because Policy was reached only from the Tool adapter, that omission also removed expected
critical Policy evidence even though the existing Goal Router and registries had already resolved a
unique capability.

## Decision

Compose a deterministic critical capability envelope from the existing Goal Router, Tool Registry,
Tool Policy Profile Registry, and Argument Binder. Evaluate Policy for supported, fully bound
critical capabilities before the model session, and record unsupported RX intent as a deterministic
deny without exposing an RX Tool.

After the model session, validate required critical completeness against schema-validated formal Tool
evidence. Permit one deterministic repair only where the envelope supplies a unique missing Tool and
all required arguments. The repaired Tool traverses the unchanged Policy, confirmation, Reliable
Executor, persistence, and audit path. Otherwise fail safely.

## Consequences

- Critical Policy coverage no longer depends on model Tool emission.
- A missing or invalid Tool proposal remains independently visible and cannot be hidden by Policy
  evidence.
- Ordinary non-critical requests incur no additional model call.
- The guard cannot add optional actions, broaden goals, retry indefinitely, or expose safety-critical
  vehicle actuators.
- Provider determinism is neither required nor claimed for the critical safety invariant.
